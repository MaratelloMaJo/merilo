# ADR-002. Три шлюза проверки по возрастанию стоимости

- **Статус:** принято
- **Дата:** 2026-11-07
- **Контекст:** нужно оценивать присланный код, но нельзя платить за модель на каждом
  заведомо сломанном или враждебном запросе.

## Контекст

Проверка решения состоит из операций разной цены и разной надёжности:

1. разбор кода — микросекунды, детерминированно, локально;
2. поиск попыток подменить инструкции оценщика — миллисекунды, локально;
3. оценка по рубрике языковой моделью — секунды, деньги, сеть, внешние 429/503.

Если поставить модель первой, каждый `SyntaxError` и каждая попытка инъекции стоят
денег и времени. Если модель — единственный судья, то отказ внешнего API рушит демо.

## Решение

Конвейер из трёх последовательных шлюзов, каждый следующий запускается только если
предыдущий пропустил код:

| Шлюз | Что делает | Провал |
|:---|:---|:---|
| **Gate 1** | tree-sitter-разбор кода на языке задачи (`analyze_code(submitted_code, language)`) | `status="rejected"`, `gate_reached=1`, `0`, `Rejected` |
| **Gate 2** | regex-щит по известным формулировкам подмены инструкций | `status="blocked"`, `gate_reached=2`, `0`, `Rejected` |
| **Gate 3** | оценка по рубрике 30/40/30 + `sha256` + HMAC-подпись | оценка и карточка |

Правила приоритета:

- **Щит важнее синтаксиса.** Если код не парсится, но содержит императив инъекции,
  вердикт всё равно `blocked` на Gate 2 — иначе атакующий мог бы «спрятать» атаку
  в невалидном файле.
- **Отказ модели — не отказ сервиса.** Истёк таймаут, нет ключа, 404/429/5xx —
  включается детерминированная AST-эвристика (см. ADR-005), а не 5xx.

## Альтернативы

| Вариант | Почему отклонён |
|:---|:---|
| Сразу LLM-оценка | Деньги и латентность на мусорных запросах; демо зависит от квоты |
| Только статический анализ | Нет оценки архитектуры и читаемости, которые требует рубрика |
| Внешний сервис проверки кода | Чёрный ящик, нет контроля над вердиктом и ценой |

## Последствия

**Плюсы**

- Дешёвые вердикты бесплатны: инъекция и синтаксическая ошибка не доходят до сети.
- Понятная диагностика: жюри видит, на каком шлюзе остановился код.
- Модель можно отключить целиком, не ломая контракт API.

**Минусы и как компенсировано**

- Regex не понимает смысл: перефразированная атака пройдёт Gate 2. Это прямо
  написано в README и `docs/JURY_QA.md`; второй слой — флаг
  `is_plagiarized_or_injected` в ответе модели.
- Три шлюза — три места для ошибок. Покрыты тестами: `test_ast_gate.py`,
  `test_injection_shield.py`, `test_api_contract.py`.

## Доказательства

- `backend/verifier.py:573` — `verify_submission`, порядок шлюзов.
- `backend/fallback_cache.py:653` — `_dangerous_calls`, детекторы инъекций.
- `tests/test_injection_shield.py` — инъекция блокируется, документационные
  упоминания «system prompt» — нет.
- Пресеты: ideal → gate 3, vulnerable → gate 3, injection → gate 2 / 0.
