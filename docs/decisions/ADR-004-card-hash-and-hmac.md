# ADR-004. Публичная карточка: детерминированный SHA-256 идентификатор + HMAC-подпись

- **Статус:** принято
- **Дата:** 2026-11-08
- **Контекст:** карточку открывают по ссылке посторонние люди; ей нужно верить без
  доступа к базе и без логина.

## Контекст

Verified Skill Card — единственный публичный артефакт системы. Требования:

1. ссылка стабильна: один и тот же результат не должен плодить дубликаты;
2. запись нельзя отредактировать в базе, не оставив следа;
3. проверка не должна требовать авторизации или знания внутренних id.

## Решение

**Идентификатор.** `card_hash` = первые 12 hex-символов SHA-256 от кортежа
`task_id`, имя кандидата, вердикт, балл, `user_id` и SHA-256 отправленного кода.
`user_id` детерминированно выводится из нормализованного email:
`usr_` + первые 16 hex SHA-256 (`backend/db.py::create_user`).

Следствия, которые проверены:

- та же задача + тот же кандидат (email) + тот же код → тот же `card_hash`,
  в том числе на двух независимых свежих базах (`8c101d0a2a98`);
- два разных email дают разные `user_id`, поэтому карточка не «перетекает»
  между аккаунтами;
- в уже существующих базах остаются прежние `user_id` — миграции нет.

**Подпись.** Поверх содержимого считается HMAC-SHA256 секретом сервера
(`sign_card` / `verify_card_signature`), сравнение — только `hmac.compare_digest`.
Проверка доступна публично: `GET /api/cards/{hash}` возвращает
`is_signature_valid`.

**Секрет.** `MERILO_HMAC_SECRET` из окружения. В `development` без переменной
создаётся эфемерный секрет и печатается warning; в `MERILO_ENV=production`
отсутствие секрета — `RuntimeError` на старте (fail-fast, а не тихий дефолт).

## Альтернативы

| Вариант | Почему отклонён |
|:---|:---|
| Случайный UUID карточки | Не даёт детерминизма и не связывает карточку с содержимым |
| JWT как карточка | Нечего хранить и показывать; ревокация и «карточка как запись» теряются |
| Публичный ключ (Ed25519) | Честнее по смыслу, но усложняет демо: нужен формат ключей и распространение публичной части |
| Просто запись в БД без подписи | Правка строки в базе неотличима от оригинала |

## Последствия

**Плюсы**

- Ссылку можно проверить, не доверяя серверу на слово: подпись пересчитывается.
- Дубликаты не появляются: повторная отправка того же кода возвращает ту же карточку.
- Секрет ротируется одной переменной окружения.

**Минусы и как компенсировано**

- HMAC — не публичная криптография: проверяющий доверяет серверу, который хранит
  секрет. Для демо это приемлемо; переход на асимметричную подпись описан как roadmap.
- Ротация секрета инвалидирует старые карточки (`is_signature_valid=false`) →
  в README написано, что карточки нужно перевыпустить.
- `card_hash` — усечение до 12 hex (48 бит): достаточно против случайных коллизий
  в демо, но не является криптостойким идентификатором в масштабе.
