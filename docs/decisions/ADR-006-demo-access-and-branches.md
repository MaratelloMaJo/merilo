# ADR-006 — Демо-доступ без регистрации и разделение веток

- **Статус:** принято (2026-11-09); раздел 3 «Ветки» изменён 2026-11-13 — инфраструктура перенесена в основную ветку релиза
- **Дата:** 2026-11-09
- **Контекст:** сдача кейса NFC 2026, демо на Fly.io, защита 14 ноября

## Контекст

Жюри открывает ссылку и первым делом видит форму входа/регистрации: кнопки быстрого
входа только подставляют email и требуют пароль (пароли намеренно убраны из клиента
в P0.4). Для человека, который смотрит продукт 60 секунд, это выглядит как
«незаконченный стартап», а не как готовый инструмент. При этом бэкенд уже
zero-auth: `POST /api/submissions/verify` принимает запрос без токена, а
`GET /api/auth/me` при отсутствии токена отдаёт первого пользователя.

Второй риск — устойчивость на неделю до офлайн-отбора: на Fly нет volume,
SQLite лежит внутри контейнера и стирается при каждом `fly deploy` (сиды
восстанавливаются, карточки, созданные жюри, — нет).

Третий запрос — разделить репозиторий: `main` как чистый код для локального
запуска, отдельная ветка со всей инфраструктурой.

## Решение

### 1. Демо-доступ: флаг + один аккаунт + две роли

- Новый флаг окружения `MERILO_DEMO_MODE` (по умолчанию `0`).
- Эндпоинт `POST /api/demo/session` существует только при `MERILO_DEMO_MODE=1`;
  иначе `404`. Возвращает `{token, user}` для демо-аккаунта, где `token` —
  обычный `create_session_token(user_id)`, тот же, что выдаёт `/api/auth/login`.
- Демо-аккаунт — `marat@merilo.kz`, роль `owner` (схема `users.role` — свободный
  `TEXT`, ограничений нет). `formatRole` в UI отображает `owner` как «Основатель».
- Фронтенд при загрузке: если `POST /api/demo/session` отвечает 200 — вход
  выполняется молча, экран авторизации не показывается, в шапке остаётся
  переключатель «Кандидат / HR», обе проекции доступны одной сессии.
- Вход и регистрация не удаляются: они спрятаны за ссылкой «Полный режим» внизу
  экрана, чтобы продукт не выглядел «демо-заглушкой» и жюри могло посмотреть
  реальный auth-флоу.
- Пароль демо-аккаунта не нужен и не печатается; в демо-режиме сидинг не
  требует `MERILO_DEMO_PASSWORD`.

### 2. Устойчивость: volume + entrypoint

- Fly volume `merilo_data` (1 GB, регион `fra`), монтируется в `/data`.
- `MERILO_DB_PATH=/data/merilo.db` — база переживает рестарт, suspend и редеплой.
- Volume принадлежит root, а приложение работает под uid 10001, поэтому в образ
  добавляется `docker-entrypoint.sh`: он создаёт каталог, делает
  `chown -R 10001:10001 /data` и через `setpriv --reuid=10001 --regid=10001
  --clear-groups` запускает исходный `CMD`. Контейнер стартует root-ом на доли
  секунды и сразу сбрасывает привилегии.
- `min_machines_running=1`, `auto_start_machines=true`, health-check
  `GET /api/health` каждые 30 с — уже настроены; добавляется только volume.

### 3. Ветки: `main` — код, `deploy` — инфраструктура

- `main`: `backend/`, `static/`, `tests/`, `scripts/`, `sql/`, `docs/`,
  `requirements*.txt`, `README.md`, `pyproject.toml`, `screenshots/`,
  `presentation.html`, `Merilo_NFC_Pitch.pptx`.
- `deploy`: то же плюс `Dockerfile`, `.dockerignore`, `fly.toml`, `render.yaml`,
  `.github/workflows/ci.yml`.
- Деплой идёт из отдельного worktree `../merilo-deploy` (ветка `deploy`), поэтому
  рабочая папка остаётся на `main` и инфраструктура не может случайно попасть в
  «чистый» коммит.
- README не ломается: скриншоты и презентация остаются в `main`.

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| Один общий пароль, показанный жюри | Печать под таймером на защите — лишний риск опечатки; не решает «заводской вид» |
| Полностью убрать вход | Теряется демонстрация аккаунтов и подписи карточки именем |
| Хранить SQLite в контейнере | `fly deploy` стирает карточки жюри; «неделя устойчивости» не выполняется |
| Оставить одну ветку | `main` перестаёт быть чистым кодом, как просил владелец |
| Перевести `db.py` на PostgreSQL | Слишком большой объём перед защитой, риск сломать рабочую демонстрацию |

## Последствия и риски

- `MERILO_DEMO_MODE` **выключен по умолчанию**: на локальной машине и в тестах
  поведение не меняется, эндпоинт отвечает 404.
- Демо-сессия даёт полный доступ к демо-аккаунту без пароля. Это осознанное
  решение для публичной демонстрации; данные в ней нечувствительные, а запись
  ограничена rate-limit-ом.
- Роль `owner` — новое значение в свободном поле `role`; старые значения
  (`candidate`, `recruiter`) продолжают работать, миграция не нужна.
- Entrypoint на старте работает от root: контейнер не становится root-овым
  процессом, привилегии сбрасываются до запуска приложения.
- Ветка `deploy` — отдельная точка правды для инфраструктуры; при расхождении
  веток `deploy` перебазируется на `main` перед деплоем.

## План реализации

1. `backend/main.py`: эндпоинт `POST /api/demo/session` под флагом
   `MERILO_DEMO_MODE`; `backend/seed_data.py` — роль `owner` для демо-аккаунта в
   демо-режиме.
2. `static/app.js` + `static/i18n.js`: молчаливый вход при старте, скрытие
   auth-экрана, ссылка «Полный режим», подпись роли `owner`.
3. `Dockerfile` + `docker-entrypoint.sh`: chown volume и сброс привилегий.
4. `fly.toml`: `[mounts]` на `/data`, `MERILO_DB_PATH=/data/merilo.db`,
   `MERILO_DEMO_MODE=1`.
5. Ветки: создать `deploy` от текущего `main`, убрать инфраструктуру из `main`,
   добавить worktree `../merilo-deploy`.
6. Тесты: демо-эндпоинт включён/выключен, маппинг роли, неизменность остальных
   контрактов; полный прогон `pytest`, `ruff`, `node --check`.
7. Документация: этот ADR, строка в `docs/decisions/README.md`, абзац в README
   про демо-режим.

## Проверка

- `MERILO_DEMO_MODE=0` → `POST /api/demo/session` возвращает 404, прежние тесты
  зелёные.
- `MERILO_DEMO_MODE=1` → 200, токен валиден, `/api/auth/me` возвращает `owner`.
- После деплоя: открыть `https://merilo-nfc.fly.dev` в приватном окне — сразу
  кабинет, без формы; переключить «Кандидат → HR»; проверить пресет и карточку.
- `fly deploy` повторно → карточка, созданная до деплоя, остаётся доступной.

## Вне рамок

- Настройка таймаутов Gemini (холодный verify ~12,8 с) — отдельная задача.
- Перенос на PostgreSQL и любые изменения схемы БД.
- Удаление регистрации в не-демо режимах.

## Поправка 2026-11-13: ветки объединены

Разделение `main` / `deploy` отменено для финального релиза. Причина: за месяцы
разработки `deploy` разошёлся с кодом, и merge вернул бы старые версии файлов.
Инфраструктура перенесена в ветку релиза выборочно:
`git checkout deploy -- Dockerfile .dockerignore fly.toml docker-entrypoint.sh render.yaml .github/workflows/ci.yml`.
`Dockerfile` дополнен `COPY docs/ ./docs/` (страница `/evidence/{document}` читает
документы из `docs/`), `.dockerignore` исключает `.env`, `*.db`, агентские
каталоги и черновики, а `docker-entrypoint.sh` закреплён с LF через
`.gitattributes` — иначе Windows-checkout ломает shebang.

Прежние пункты 3 и «Последствия» о `deploy` как отдельной точке правды считаются
историческими; актуальное состояние — один релизный набор в основной ветке.
Entrypoint использует `python os.setuid`, а не `setpriv`: `setpriv` отсутствует в
`python:3.12-slim`.
