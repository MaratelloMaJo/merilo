# ADR-005. Детерминированный офлайн-fallback вместо фиктивных оценок

- **Статус:** принято
- **Дата:** 2026-11-08
- **Контекст:** демо не должно зависеть от квоты Gemini, но и не должно врать
  о том, что показало «оценку ИИ».

## Контекст

Первый прототип возвращал заготовленные оценки для пресетов: красиво на сцене,
бесполезно как продукт и опасно как обещание. Плюс внешняя модель может ответить
429/503, истёкнуть по таймауту или просто отсутствовать ключ — а демо в этот момент
идёт перед жюри.

## Решение

1. **Заготовленные оценки удалены.** `PRESET_EVALUATIONS` больше нет: балл всегда
   считается из фактически присланного кода.
2. **Fallback — это AST-эвристика**, а не заглушка. Она разбирает присланный код и
   считает те же три блока рубрики по измеримым признакам: наличие docstring и
   аннотаций типов, `bare except`, обработка пустых входов, проверки деления на ноль,
   опасные вызовы (`eval`, `exec`, `pickle`), SQL-конкатенация, мутабельные дефолты,
   проверка положительной суммы, идемпотентная дедупликация и т. д.
3. **Источник оценки всегда виден.** В ответе и на карточке есть
   `evaluation_mode` (`gemini` / `fallback`), `confidence` (`high` / `low`) и
   `fallback_reason`. Fallback не маскируется под модель.
4. **Модель вызывается по цепочке:** `GEMINI_MODEL` (по умолчанию
   `gemini-3.6-flash`) → `gemini-3.5-flash` → `gemini-3.5-flash-lite`, с
   `temperature=0.0`, `response_mime_type="application/json"` и
   `response_schema=CodeEvaluationResponse`, таймаутом 6 с и одним retry.
   Причина отказа попадает в `fallback_reason`.
5. **Кэш реальных ответов** — TTL-кэш по SHA-256 от `task_id` + модели + кода:
   повторная проверка того же решения не жжёт квоту и возвращает тот же результат.

## Альтернативы

| Вариант | Почему отклонён |
|:---|:---|
| Заготовленные баллы для демо | Прямой обман жюри; ломается на любом новом коде |
| 500 при недоступной модели | Демо умирает из-за внешнего 429 |
| «Тихий» fallback без пометки | Пользователь думает, что это оценка модели |
| Локальная модель (Ollama) | Тяжёлая зависимость, непредсказуемое время старта в зале |

## Последствия

**Плюсы**

- Демо работает без интернета и без ключа; 9/9 пресетов воспроизводятся.
- Баллы честно зависят от кода: другая реализация — другой балл.
- Отказ внешнего API виден в логах (`fallback_reason`), а не скрыт.

**Минусы и как компенсировано**

- Эвристика грубее модели: она не понимает замысел, только признаки. Поэтому
  `confidence="low"` и явная подпись «детерминированная эвристика».
- Два пути оценки нужно держать согласованными по контракту → оба возвращают
  `CodeEvaluationResponse`, покрыто `tests/test_fallback.py`.
- Fallback можно «обыграть» признаками (docstring без смысла). Это ограничение
  эвристики, а не заявка на семантическую проверку.
