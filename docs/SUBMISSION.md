# Сдача решения — National Founder Cup 2026 (Шымкент)

Практическая памятка: что именно сдаётся, в какие сроки и что проверить перед дедлайном.
Источник — страница кейса на hackathon.kz (`national-founder-cup-shymkent-2026`)
и регламент мероприятия. Если правило на сайте поменяется, приоритет у сайта.

## 1. Ключевые даты

| Этап | Дата | Что это значит для нас |
|:---|:---|:---|
| Онлайн-этап | 5–9 ноября 2026 | Работа над решением, коммиты в `main` |
| **Дедлайн онлайн-этапа** | **9 ноября, 23:59** | Платформа фиксирует **последний коммит ветки `main`** |
| Материалы финала | до 12 ноября, 23:59 | Техдокументация + презентация (PDF/PPTX) + ссылка на репозиторий/демо |

| Защита онлайн для иногородних | уведомить до 12 ноября, 23:59 | Если команда не из Шымкента |

## 2. Как технически происходит сдача

Сдача идёт через форму **«Проект»** на странице кейса на hackathon.kz. Поля:

| Поле | Лимит |
|:---|:---|
| Название проекта | 200 символов |
| Описание | 5 000 символов |
| Ссылки | произвольный список, подпись + URL (демо, презентация, репозиторий) |
| Файлы | до 5 штук, до 20 МБ каждый: `.pdf .ppt .pptx .key .doc .docx .zip`, картинки |

Кнопка **«Отправить жюри»** — единственное, что делает проект видимым жюри.
«Сохранить черновик» виден только команде и организаторам. После дедлайна проект
не меняется.

Практические следствия:

1. Всё, что должно быть оценено, лежит в `main` — не в ветке, не в stash, не в архиве.
   Организаторы фиксируют состояние ветки `main` на момент закрытия этапа.
2. `.env` и любые ключи в репозиторий не попадают: это правило и это риск
   дисквалификации. В репозитории только `.env.example` с пустыми значениями.
3. Файлы больше ~100 МБ не коммитятся — на них даётся внешняя ссылка. В форму
   видео тоже не грузится: только ссылкой на YouTube или Диск.
4. Репозиторий должен открываться без нас: README, запуск одной командой, тесты.
5. `.html` в список принимаемых файлов не входит — дека едет либо как PDF/PPTX,
   либо ссылкой на хостинг статики.
6. Готовый текст всех полей — [`docs/SUBMISSION_TEXT.md`](SUBMISSION_TEXT.md),
   деплой демо — `Dockerfile`, `fly.toml`, `render.yaml` в корне репозитория.

## 3. Что входит в техдокументацию финала

По регламенту — шесть пунктов. Где они закрыты в этом репозитории:

| Требование | Где смотреть |
|:---|:---|
| Проблема | `README.md` → «Проблема»; `docs/PROBLEM.md` |
| Решение | `README.md` → «Что делает Merilo» |
| Функциональность | `README.md` → «Демо за 60 секунд»; `docs/DEMO.md` |
| Технологии | `README.md` → «Архитектура»; `docs/decisions/` |
| Реализация | `backend/`, `static/`, `tests/`, `Dockerfile` |
| Текущее состояние | `docs/READINESS.md`, `docs/FINAL_REPORT.md`, `docs/FINAL_AUDIT.md` |

## 4. Презентация и защита

- Формат файла: **PDF или PPTX**. Исходник деки — `presentation.html`
  (статический HTML, открывается локально) и `scripts/generate_pitch.mjs` (сборка PPTX и HTML).
- Регламент: **4 минуты презентации с демо + 2 минуты вопросов**.
- Язык: казахский или русский.
- Демо — живьём, на ноутбуке, без интернета: `python scripts/run_demo.py`,
  ключ Gemini не нужен, оценки считает детерминированный fallback.
- Резерв: `docs/offline-demo.html` и скриншоты в `screenshots/` на случай,
  если в зале не поднимется сеть или браузер.

## 5. Видео-демо

**Регламент не требует видео.** Нужен живой прототип на защите. Короткая запись
экрана (60–90 секунд) — необязательная страховка: её можно показать, если в зале
не запустится окружение. Записывать её специально ради сдачи не нужно.

## 6. Docker-образ

**Заливать образ в registry не требуется.** `Dockerfile` в репозитории — это
доказательство развёртываемости, а не обязательный артефакт сдачи. Жюри смотрит
код и запуск; образ собирается из репозитория одной командой:

```bash
docker build -t merilo .
docker run --rm -p 8000:8000 -v merilo-data:/app/data merilo
```

Образ собран и прогнан локально 2026-11-13: 326 МБ, `python:3.12-slim`, non-root `uid 10001`,
`HEALTHCHECK` на `/api/health`, внутри нет `.env` и `*.db`; `/evidence/{document}` читает
`docs/` из образа. Smoke-прогон всех маршрутов — `docs/FINAL_AUDIT.md` §2.

## 7. Чек-лист перед дедлайном

- [ ] `git status` чистый, всё нужное в `main`.
- [ ] `python -m pytest -q --cov=backend --cov-fail-under=80` — зелёный (факт 2026-11-13: 397 passed, 85,30 %).
- [ ] `python -m ruff check backend tests scripts` — без замечаний.
- [ ] `python -m compileall -q backend tests scripts` — exit 0.
- [ ] `.env` не отслеживается: `git ls-files | findstr .env` показывает только `.env.example`.
- [ ] README открывается и объясняет проект без запуска кода.
- [ ] Скриншоты и ссылки из README существуют (нет битых путей).
- [ ] Презентация экспортирована в PDF/PPTX и лежит рядом с решением.
- [ ] Проверен запуск на чистой машине: `python scripts/run_demo.py`.
- [ ] Нет файлов больше 100 МБ в истории коммита.
- [ ] Форма заполнена по [`docs/SUBMISSION_TEXT.md`](SUBMISSION_TEXT.md), ссылки вставлены.
- [ ] Демо и презентация открываются по ссылкам **с чужого устройства**, без входа.
- [ ] Нажата **«Отправить жюри»**: статус этапа сменился с «Не начат» на отправленный.
